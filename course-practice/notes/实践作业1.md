## 实际用过的工具

代码阅读和统计没有使用商业“一键注释”插件。结构统计用 Python 包 javalang 0.13.0 解析全部 Java 文件，39 个基线文件都解析成功，再由 `course-practice/tools/count_sources.py` 输出 CSV。行数同时用 `wc -l` 核对。这样做的原因是课件要求给出包、类、方法数量，而口头估计的“大约一万行”没有口径。

构建工具是 Gradle 8.9 和 Android Gradle Plugin 8.5.2，SDK 使用命令行 `sdkmanager`，不是 Android Studio 向导。测试分成两层：不依赖 Android 的 `javac` 程序 `RunToolTests`，以及用 Python `sqlite3` 核对回收站触发器语义的脚本。静态检查没有再跑完整的 Android Lint 门禁，`build.gradle` 里把 Lint 失败设为不中断打包，因为旧工程有大量历史警告，把它们全部清掉会超出两项功能的范围。

## 遇到的问题

工程根目录只有 `AndroidManifest.xml`、`src`、`res` 和 `README`，没有 `build.gradle`。这是 Eclipse ADT 时代的小米便签社区版，不能直接在当前 Android Studio 新建工程的假设下打开。另一个问题是课件把“代码自动注释工具”列成需要了解的对象。自动给每个方法生成一句中文，很容易把没读过的方法写成错误功能。因此类注释是读过声明和职责后逐个写入的；方法、语句块和关键语句注释只加在字数统计、回收站策略和对应调用点上。
