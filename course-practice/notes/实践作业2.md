## 找到的工程

课件示例仓库是 MiCode/Notes。本次部署的是用户仓库里已经存在的那一份社区版源码，应用包名 `net.micode.notes`，版本名 0.1。README 写明它是 MIUI 便签的社区开源版，协议见 `NOTICE`（Apache License 2.0）。源码语言是 Java，清单里的原始 `minSdkVersion` 是 14。

## 云端实际安装了什么

机器上原来只有 OpenJDK 21，没有 `ANDROID_HOME`，也没有 `adb`。随后下载了 Android 命令行工具，并安装：

- platform-tools
- platforms;android-34
- build-tools;34.0.0
- 后来为模拟器另装 emulator 与 `system-images;android-34;aosp_atd;x86_64`

Gradle 使用 8.9 发行包。工程新增根目录 `build.gradle`、`settings.gradle`、`gradle.properties` 和 wrapper。`local.properties` 只在这台云端机器上指向 `/home/ubuntu/android-sdk`，已加入 `.gitignore`，不能提交，否则会把云端路径写进别人的工作副本。

## 编译时真正碰到的问题

1. `GTaskClient` 引用 `org.apache.http.*`。API 23 之后这些类不在 `android.jar`。platform 34 的 `optional/org.apache.http.legacy.jar` 存在，因此在 Gradle 里写了 `useLibrary "org.apache.http.legacy"`。
2. `GTaskASyncTask.showNotification` 调用 `Notification.setLatestEventInfo`。该方法在当前 `android.jar` 中已经没有，编译会失败。改成 `Notification.Builder`，并在 API 26 及以上创建渠道 `gtask_sync`。这是为了能编过，不是新功能。
3. Android Gradle Plugin 8 默认让 `R.id` 不是 final，旧代码里的 `switch (item.getItemId())` 无法编译。`gradle.properties` 设置 `android.nonFinalResIds=false`。
4. 为了能安装到 Android 12 及更新的系统，清单把 minSdk 从 14 调到 21，targetSdk 设为 34，并为带 intent-filter 的组件补上 `android:exported`。Provider 设为不导出。PendingIntent 补了 `FLAG_IMMUTABLE`。这些都记在兼容修改里，不记成产品需求。
5. JDK 21 提示“用 Java 8 作为 source/target 已过时”。编译仍然成功，没有为了消掉这三条警告去改全部源码的语言级别。

## 构建结果

`./gradlew assembleDebug` 结果是 `BUILD SUCCESSFUL`。日志在 `course-practice/logs/assembleDebug.log`，结束行带 `EXIT:0`。产物复制为 `course-practice/dist/notes-debug.apk`，大小约 1.1 MB。`aapt dump badging` 读到：包名 `net.micode.notes`，versionName `0.1`，sdkVersion 21，targetSdkVersion 34，启动 Activity 是 `net.micode.notes.ui.NotesListActivity`，中文标签为“便签”。

随后安装了无界面模拟器。第一次启动失败，原因是 `/dev/kvm` 属于 root 且当前用户不在该组，日志原文是 “This user doesn't have permissions to use KVM”。把设备权限放开后再次启动，日志有 “Boot completed in 22438 ms”，`adb devices` 出现 `emulator-5554`。`adb install` 成功。

`screencap` 得到的 1080×1920 图片每个像素都是黑色，不能当作界面截图。界面证据来自 `uiautomator` 层次和 `run-as` 读出的 `note.db`，写在 `logs/emulator-ui-evidence.txt`。编辑页出现 “26 chars · 1 lines”，与介绍句的码点数一致。删除对话框英文是 “Move this note to trash? You can restore it later.”。确认后这条记录的 `parent_id` 变为 -3。列表菜单里有 Trash。恢复按钮能在层次里看到，但点击没有改数据库，所以恢复的界面动作仍算未在模拟器上点通。用户本机复现步骤见 `windows/本机复现步骤.md`。本机如果得到正常截图，用本机图片替换这张黑图，不要把黑图贴进报告里假装是界面。

## LLM 的作用

助手选择了命令行 SDK 而不是要求这台无界面机器安装 Android Studio，并在编译错误出现后改了通知 API、资源 id 和清单属性。它没有把未执行的模拟器步骤写成已经看到便签界面。
