## 为什么是这两项

阅读 `NotesListActivity.batchDelete` 可以看到：只有设置了同步账号，删除才把 `parent_id` 改成 `Notes.ID_TRASH_FOLER`（-3）；否则调用 `batchDeleteNotes` 直接删行。列表菜单和根目录查询都没有进入 id 为 -3 的入口。数据库里的回收站因此对普通使用几乎不可见，误删不能恢复。这是第一项改进：不论是否配置同步，普通删除都先移入回收站；提供回收站列表、恢复和清空；已经在回收站里的删除才物理删除。

第二项来自编辑页。`note_edit.xml` 只显示修改时间和提醒，没有字数，清单模式也看不出完成了几项。字数可以在界面上算，不必改表。两项都落在已经读过的列表、编辑、`DataUtils` 和数据库触发器上，范围比新做一套标签系统小，而且能用没有模拟器的 JVM 测试核心判断。

没有把“修复 Google Tasks 同步”选进来。那个客户端调用的是旧接口，本次不能验证服务端，硬改请求格式会变成没有证据的网络代码。

## 实现要点

`TrashPolicy` 不引用 Android。`decide` 对四个系统文件夹返回拒绝；父 id 已是 -3 时返回永久删除；其他情况返回移入回收站。`restoreParent` 在原父 id 为回收站或临时文件夹时回到根目录 0；原用户文件夹已不存在时也回到 0；根目录和通话文件夹按原 id 返回。`DataUtils.moveNotesToTrash` 在更新 `parent_id` 的同时写入已有列 `origin_parent_id`。原来的 `batchMoveToFolder` 不写这一列，所以恢复不能复用它。

文件夹被移入回收站时，原触发器只把子行的 `parent_id` 改成 -3，子行的 `origin_parent_id` 仍是默认 0，恢复时会掉到根目录。数据库版本从 4 升到 5，只重建这条触发器，让子行的 `origin_parent_id` 等于被移动文件夹的 id。没有新表，也没有新列。版本 4 的 `onUpgrade` 路径增加 `upgradeToV5`。新建库直接执行新的触发器 SQL。

字数在 `NoteTextMetrics.analyze`。字按 Unicode 码点计，emoji 算 1 个而不是 2 个 UTF-16 单元。空文本为 0 行；以换行结尾时不额外增加一行；中间空行保留。行在去掉空白后若以 `√` 或 `□` 开头，计入清单。编辑页在普通文本变化、清单勾选和拆行时刷新 `tv_note_metrics`。结果只显示，不写入 `note` 或 `data`。

## 测试

`course-practice/jvm-tests/RunToolTests.java` 用 `javac` 编译 `NoteTextMetrics` 和 `TrashPolicy` 后运行。覆盖空文本、汉字、emoji、行规则、清单标记、系统文件夹拒绝、恢复目标。终端输出 `ALL PASSED`，失败数为 0。

`jvm-tests/test_trash_trigger.py` 做两件事：确认 `NotesDatabaseHelper.java` 的触发器源码包含 `origin_parent_id` 赋值且 `DB_VERSION` 为 5；在内存 SQLite 中执行同语义的触发器。插入文件夹 7 和子便签 8，把文件夹父 id 改为 -3 后，子便签父 id 为 -3、`origin_parent_id` 为 7。输出两条 PASS。这个测试不是在 Android 设备上打开 `note.db`，不能代替真机升级旧版本数据库。

模拟器上的补充结果写在 `logs/emulator-ui-evidence.txt`。编辑页层次出现 “26 chars · 1 lines”，和介绍句的 26 个码点一致。删除确认框是移入回收站的英文提示，确认后 `parent_id` 为 -3。列表能进入 Trash。恢复按钮出现了，但点击没有把 `parent_id` 改回去，因此设备上的恢复仍未验证。`screenshots/` 里只有一张全黑的 framebuffer，不能当作界面截图。

## 精读注释的范围

`NoteTextMetrics` 和 `TrashPolicy` 的类、方法、语句块、关键语句都有中文注释，例如码点循环不能用 `charAt` 逐个 `char`，以及“只有父 id 已经是回收站才物理删除”。`DataUtils` 新增方法有方法级说明。旧的 `batchDeleteNotes` 保持原样，避免把无关历史代码改出行为差异。

## LLM 的作用

助手提出这两项是因为它们对应源码里的具体缺口，而不是先想一个新业务再往回套。测试断言是助手编写的，但是通过与否以 `java` 和 `python3` 的退出码为准。
