## 主体功能，按包而不是按想象

`ui` 是使用者能看见的部分：列表 `NotesListActivity`、编辑 `NoteEditActivity`、设置、提醒界面、日期选择。`data` 定义 `note` 与 `data` 两张表的列、SQLiteOpenHelper 和 ContentProvider。`model` 的 `Note`、`WorkingNote` 负责把编辑中的内容写成 Provider 操作。`tool` 做导出、批量删除和移动、背景色资源映射。`widget` 是 2×2 和 4×4 桌面小部件。`gtask` 是 Google Tasks 同步，网络代码在 `GTaskClient`，用的是已经停用的私有 HTTP 接口；不同步时这些类不会在打开便签时执行。

数据库在改动前就是版本 4，只有 `note` 和 `data`。系统文件夹写死为 id 0（根）、-1（临时）、-2（通话）、-3（回收站）。回收站行在建库时就插入，但列表查询不会把它当成普通文件夹显示出来。这一点留到作业 4 和作业 5，因为泛读时已经能从 `NotesListActivity` 的菜单里确认没有“回收站”入口。

## 泛读时遇到的具体问题

工程没有 Gradle，IDE 的“工程视图”在这台机器上不存在，包结构只能从目录和 `package` 声明来。`javalang` 第一次把内部类的包名拼错，方法被记到不存在的包上。发现包文件数加总不是 39 之后改了遍历方式，重新生成 CSV，并以 4+6+2+4+2+4+14+3=39 作为核对。若没有这次核对，报告里的包数量会是错的。

另一个容易错的地方是把匿名监听器里的 `onClick` 算进类的方法。脚本因此分成“具名类型方法”和“匿名类方法”。作业如果只写一个方法总数，需要说明用的是哪一列。
