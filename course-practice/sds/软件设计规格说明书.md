## 1. 文档概述

本文把 SRS 中的保留功能和两项改进落到类、界面和表。已经写进 APK 的设计与仅仅画出的拟新增表分开标注。

## 2. 系统概述

应用仍是单进程里的列表 Activity、编辑 Activity、ContentProvider 和 SQLite。改进不增加进程，不增加应用模块。显示名不改。回收站是 `note` 表里 `parent_id = -3` 的行集合，不是新的系统应用。

## 3. 设计目标和原则

- 原有列表、编辑、清单、搜索、导出、提醒、小部件的调用路径尽量不改。
- 能放进纯 Java 类的判断就不要写进 Activity，以便没有设备时测试。
- 不为回收站复制正文。恢复使用已有列 `origin_parent_id`。
- 文档里出现的表，要么能在 `CREATE TABLE` 里找到，要么明确写“拟新增，未建表”。

## 4. 设计约束和现实限制

- 源码原为 Eclipse 工程。当前构建是 Gradle，compileSdk 34，minSdk 21，targetSdk 34。
- `GTaskClient` 仍依赖 Apache HttpClient 旧库，由 `useLibrary "org.apache.http.legacy"` 打进 APK。同步设计不在本次变更内。
- `Notification.setLatestEventInfo` 无法对当前 android.jar 编译，通知改为 `Notification.Builder`。这是构建约束下的替换，SRS 没有新的通知需求。
- targetSdk 34 要求带 intent-filter 的组件声明 `exported`，PendingIntent 带不可变标志。
- 版本 4 的旧库升级到版本 5 的路径写在 `onUpgrade`，但没有拿一份真实的版本 4 数据库文件在设备上跑过。

## 5. 体系结构（包含原有功能）

逻辑分层保持原状。

- 表现：`ui` 与 `widget`。列表、编辑、设置、提醒、小部件。
- 应用模型：`WorkingNote`、`Note`。
- 数据访问：`NotesProvider`、`DataUtils`、`NotesDatabaseHelper`。
- 同步：`gtask`，本次不改协议。

R1 加在表现层和新建的 `NoteTextMetrics` 之间。R2 加在列表/编辑的删除分支、`TrashPolicy` 和 `DataUtils` 的新方法之间。原有搜索 SQL 仍排除 `parent_id = -3`，所以回收站不会出现在搜索结果里，这是有意保留的结构。

## 6. 用户界面设计（新增功能）

图 7（`diagrams/fig-07-ui-prototype.png`）是原型，不是运行截图。

- 列表：根菜单增加“回收站”。原有新建、文件夹、导出、同步、设置、搜索保留。
- 编辑：标题区域下方增加 `tv_note_metrics`。普通模式显示“N 字 · M 行”，有清单标记时显示“N 字 · 清单 a/b”。字符串有英、简体、繁体三份。
- 回收站：标题栏显示“回收站”，隐藏新建按钮。多选菜单隐藏“移动”，显示“恢复”。选项菜单为“清空回收站”。删除确认文案在普通位置和回收站不同，避免都叫“删除”但语义不同。

顺序图用图 2 和图 3。类图用图 4。从回收站再点进一个文件夹后按返回，仍沿用原来的“子文件夹返回根目录”逻辑，本次没有做文件夹栈。这是界面限制，不是需求里的恢复失败。

## 7. 子系统 / 构件设计（可选）

不新增 APK 模块或 AAR。新类放在原包 `net.micode.notes.tool`，随同一应用编译。

## 8. 用例设计（新增功能）

### 8.1 查看字数

前置：打开一条文本或清单。主路径：每次文本、勾选或拆行后，`NoteEditActivity.refreshNoteMetrics` 取当前字符串，调用 `NoteTextMetrics.analyze`，设置文本视图。后置：数据库字节不变。异常：视图尚未创建时方法直接返回。

### 8.2 移入回收站并恢复

前置：便签不在四个系统文件夹 id 上。主路径：确认后 `moveNotesToTrash`。使用者打开回收站，多选恢复，`restoreNotesFromTrash` 按 `TrashPolicy.restoreParent` 写回父 id，并把 `origin_parent_id` 置 0。另一路径：在回收站确认删除或清空，调用原有 `batchDeleteNotes`。

## 9. 类设计（至少两个关键类）

### 9.1 NoteTextMetrics

位置：`src/net/micode/notes/tool/NoteTextMetrics.java`。无 Android 依赖。

- `analyze(String): Summary`
- `splitLines(String): String[]`，包内可见，测试可通过统计结果间接覆盖。
- 嵌套类 `Summary`：`codePoints`、`utf16Units`、`nonWhitespaceCodePoints`、`lines`、`checklistItems`、`checklistDone`。

不变量：`checklistDone <= checklistItems`。`checklistItems` 只统计 trim 之后以前缀 `√` 或 `□` 开头的行。

### 9.2 TrashPolicy

位置：`src/net/micode/notes/tool/TrashPolicy.java`。无 Android 依赖。常量与 `Notes` 中 0、-1、-2、-3 相同，类注释写明必须一起改。

- `decide(long noteId, long parentId): DeleteAction`
- `restoreParent(long originParentId, boolean originFolderStillExists): long`
- `isSystemFolder(long): boolean`
- 枚举 `DeleteAction`：`MOVE_TO_TRASH`、`PURGE`、`REJECT`

调用这些类的原有类是 `NoteEditActivity`、`NotesListActivity`、`DataUtils`。`DataUtils` 不是第三个“关键新类”，但它包含访问 ContentResolver 的方法，无法在本次 JVM 测试里执行。

## 10. 数据设计

### 10.1 已有表 note（不是本次新建）

来源：`NotesDatabaseHelper` 的 `CREATE_NOTE_TABLE_SQL`。版本 5 没有对它 `ALTER TABLE`。

| 列 | 定义（源码） | 与本次的关系 |
| --- | --- | --- |
| _id | INTEGER PRIMARY KEY | 主键 |
| parent_id | INTEGER NOT NULL DEFAULT 0 | 回收站用值 -3 |
| alert_date | INTEGER NOT NULL DEFAULT 0 | 未改 |
| bg_color_id | INTEGER NOT NULL DEFAULT 0 | 未改 |
| created_date | INTEGER NOT NULL DEFAULT (strftime('%s','now')*1000) | 未改 |
| has_attachment | INTEGER NOT NULL DEFAULT 0 | 未改 |
| modified_date | INTEGER NOT NULL DEFAULT (strftime('%s','now')*1000) | 未改 |
| notes_count | INTEGER NOT NULL DEFAULT 0 | 未改 |
| snippet | TEXT NOT NULL DEFAULT '' | 未改 |
| type | INTEGER NOT NULL DEFAULT 0 | 0 便签，1 文件夹，2 系统 |
| widget_id | INTEGER NOT NULL DEFAULT 0 | 未改 |
| widget_type | INTEGER NOT NULL DEFAULT -1 | 未改 |
| sync_id | INTEGER NOT NULL DEFAULT 0 | 未改 |
| local_modified | INTEGER NOT NULL DEFAULT 0 | 移入和恢复时置 1 |
| origin_parent_id | INTEGER NOT NULL DEFAULT 0 | 移入时写下原父 id；恢复后写回 0 |
| gtask_id | TEXT NOT NULL DEFAULT '' | 未改 |
| version | INTEGER NOT NULL DEFAULT 0 | 这是行版本列，不是数据库文件版本 |

数据库文件版本由 `DB_VERSION` 表示，现为 5。系统行 id：0 根，-1 临时，-2 通话，-3 回收站。源码标识符拼写 `ID_TEMPARAY_FOLDER`、`ID_TRASH_FOLER` 保持原样。

版本 5 的触发器 `folder_move_notes_on_trash`：当一行的新 `parent_id` 为 -3 时，把原来以该行 id 为父的子行更新为 `parent_id = -3` 且 `origin_parent_id = old._id`。内存 SQLite 试验见 `jvm-tests/test_trash_trigger.py`。

## 11. 接口设计（可选）

对外仍是 `content://micode_notes`。Provider 在清单中改为 `exported=false`，供本应用自己访问。没有新增 URI。移入回收站和恢复都是对已有 `content://micode_notes/note/#` 的 update。

字数没有接口。调用方直接使用 `NoteTextMetrics.analyze`。
